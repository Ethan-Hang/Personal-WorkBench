# 个人工作台 UI 原型记录

> **抛弃式原型**：用于确定信息架构和视觉方向，不作为正式应用代码继续开发。

## 要回答的问题

1. 工作台与周计划应该以什么作为第一视觉中心？
2. 长期使用时，怎样的信息密度最合适？
3. 目标、任务、习惯和总结应该如何互相衔接？

## 方案

- **A — 周历指挥台**：周时间轴是首页主体，收集箱和习惯常驻右侧。适合排程密集、习惯按日历工作的人。
- **B — 今日执行舱**：只突出今天与当前任务，目标和总结作为辅助上下文。适合减少干扰、强调执行的人。
- **C — 规划画布**：目标、里程碑和关联任务是主体，周日历压缩为摘要。适合目标驱动、规划频繁的人。

## 已确认结论

- **默认工作台采用 B 的完整今日执行舱**：聚焦今天、当前任务和快速收集，同时保留目标、习惯与总结上下文。
- **逾期任务采用摘要后展开**：首页时间线上方显示醒目摘要，由用户按需展开处理，不强制打断。
- **周日历采用 A 的周历指挥台**：作为独立一级页面，负责按日期和时间排程。
- **待排程任务使用右侧常驻抽屉**：可从抽屉直接拖到日期或时间轴。
- **目标页采用 C 的规划画布**：作为独立一级页面，展示目标、里程碑和关联任务。
- **统一视觉采用现代温暖方向**：保持 B 的现代清晰，并吸收 C 的暖色背景与克制质感。
- 整体导航关系为“目标规划 → 周日历排程 → 今日工作台执行”。

这些结论将沉淀到正式页面规格与数据模型；原型代码不直接作为生产代码继续开发。

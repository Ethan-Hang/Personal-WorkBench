# 0014. 全局时区上下文、UTC 标准化存储与时间段三者互推引擎架构

日期：2026-08-18  
状态：已接受

## 背景

在个人工作台的日常运转与排程管理中，涉及跨时区使用与时间段精细排程（分钟级）：

1. **排程时间段输入繁琐**：排程需要指定一个时间段（开始时间、结束时间、持续时长）。在传统日历中，用户需要手动算好结束时刻，无法做到「仅输入开始与时长」或「仅输入结束与时长」的直观安排；
2. **时区漂移与本地存储不对称**：浏览器仅感知本地当前系统时区，而用户可能有固定在某一时区（如上海 UTC+8）、跨时区差旅、或指定夏/冬令时（DST）的需求；若未将本地时间显式换算为 UTC 标准时刻，会导致不同终端数据读取时产生漂移；
3. **设置界面缺乏直观的世界时区地图**：用户难以一览全球时区偏差与夏令时状态。

## 决策

1. **「开始、结束、时长」三者输入其二自动推导第三者（3-Way Deduction Engine）**：
   - 在 `packages/ui/src/ScheduleRangePicker.tsx` 中实现自适应推导算法：
     - **输入 [开始] + [时长]**：自动推导 `结束时间 = 开始时间 + 时长`；
     - **输入 [开始] + [结束]**：自动推导 `时长 = 结束时间 - 开始时间`；
     - **输入 [结束] + [时长]**：自动推导 `开始时间 = 结束时间 - 时长`；
   - 提供快捷时长胶囊（`15m`、`30m`、`45m`、`1h`、`1.5h`、`2h`）与自定义分钟直输；
   - 具备即时推导辅助提示语（如 `💡 根据开始时间与持续时长 45 分钟，已自动计算结束时间为 10:15`）与合法性校验（结束必须晚于开始）。

2. **全局 TimezoneProvider 与 UTC 存储保证**：
   - 在 `packages/ui/src/TimezoneContext.tsx` 中建立全局时区状态，**默认预设为 `Asia/Shanghai`（北京/上海，UTC+08:00）**，并持久化于 `localStorage`；
   - 提供精准的 `toUtcIso` 与 `formatUtcToLocal` 双向转换管道：
     - 用户在 UI 选定本地墙钟时间后，提交前一律由 `toUtcIso` 根据当前生效时区转换为标准 UTC ISO8601 字符串（形如 `2026-08-18T07:30:00.000Z`）；
     - 服务端统一入库与截零（截去秒与毫秒），保证跨模块、跨终端的一致性。

> **2026-08-19 更新（TASK-025 / ADR-0018）**：时区偏好现已落库。三方推导只在
> `app_settings` 里没有 `timezone.id` 时才跑——库里有值就直接用，换设备不再重猜一遍。

3. **设置中心「时区与时间」子页面与交互式 SVG 世界地图**：
   - 在 `packages/web/src/pages/SettingsPage.tsx` 中新增独立二级子页面 **「时区与时间」 (`timezone`)**；
   - 嵌入高精度矢量世界地图（`TimezoneMapSelector`），提供：
     - 全球主要枢纽城市热点光标（上海、东京、伦敦、巴黎、纽约、芝加哥、洛杉矶、悉尼等）与实时脉冲波纹；
     - 悬浮即时预览当地时间，点击地图光标即刻切换全站时区；
     - 实时双核时钟仪表盘（当前时区本地时间 vs UTC 国际标准基准时间每秒同步跳动）；
     - 夏令时/冬令时（DST）状态指示与策略配置（`自动识别` / `固定冬令时` / `固定夏令时`）。

## 后果

- 排程弹窗与秋招面试轮次时间录入体验极其顺畅，用户无需心算时刻；
- 全站时间数据入库完全标准化为 UTC 格式，零时区漂移；
- 用户在设置中心拥有视觉极其出色的交互式世界地图时区配置体验。

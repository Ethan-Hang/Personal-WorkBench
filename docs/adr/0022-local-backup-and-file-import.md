# 0022. 本地数据快照、多方向导入与安全路径解析

日期：2026-08-20
状态：已接受

## 背景

本地优先应用除了基于 WebDAV 的云端备份与恢复（ADR-0020）外，还需要满足离线单机场景下的两类关键诉求：

1. **本地一致性快照与自动防灾保留**：用户在不配置云端凭据的情况下，仍能在本地磁盘对主数据库与 WAL 事务日志建立一致性快照，并在关键高危操作（如恢复、切换、删除账号）前自动生成安全快照网。
2. **本地文件导入的双向处理诉求**：
   - **方向一（覆盖当前账号）**：用户可能希望将某份历史快照（或从外部拷入的 `.db.gz`）覆盖回当前正在使用的工作区，这需要接入五态恢复机、计算差异、执行数据完整性校验并提供安全回退。
   - **方向二（导入为独立新账号）**：用户可能从其他设备拷来一份备份，希望作为一个独立新账号导入浏览，**完全不动当前账号的任何数据**，也不需要进入全服务 503 暂停态。

在实际使用中，本地快照列表项仅包含文件名（如 `2026-08-20T14-24-31-327Z.db.gz`），而本地导入允许用户从任意磁盘路径（如 USB 驱动器或自定义目录）选择备份。若前后端对纯文件名与物理路径的处理缺乏对齐，会导致预检时找不到文件（404）。

## 决策

### 1. 本地快照产物格式与云端完全同形

本地快照采用与 WebDAV 备份完全相同的物理格式：

- 数据文件：`<timestamp>.db.gz`
- 元数据文件：`<timestamp>.db.gz.meta.json`

两者共享 `BackupStore` 接口抽象（`LocalBackupStore` 与 `WebdavBackupStore` 同构），因此本地导出的快照可以直接上传至云端，反之亦然。

存储落点由配置决定：未指定 `targetDir` 时默认落在当前账号的数据子目录 `backups/`（由 `resolvedDir` 动态解析），支持自定义存储绝对目录。

### 2. 导入方向严格物理隔离

- **方向一：覆盖当前账号（走 `RestoreService`）**
  - 使用 `RestoreService.preflightLocalFile(filePath)` 进行解压与真实库水位校验（由于本地就在手边，水位直接读自 SQLite 库本身，严格杜绝旁挂 meta 伪造或缺失的问题）。
  - 点击确认后走全服务 503 五态机，操作前强制打出 `rollback.db` 回退快照，显式清理 `-wal` 与 `-shm`，确保热替换绝对安全。
- **方向二：导入为独立新账号（走 `LocalImportService`）**
  - **一个现有文件都不动**，不创建回退点，不触发全服务 503 暂停。
  - 解压后执行 `integrity_check` 校验，在独立子目录建库并立即运行全量表结构迁移（`migrate(conn)`），最后原子更新 `accounts.json`。中途失败则自动清理新建目录。

### 3. 前后端双重路径解析与防呆设计

为保证用户既能手动输入完整文件路径（如 `D:/backups/test.db.gz`），又能在 UI 上点击已有快照一键导入：

1. **前端路径拼接**：
   - `LocalBackupPanel` 与 `LocalImportModal` 获取服务端的 `config.resolvedDir`，点击已有快照列表或快捷选择 chip 时，前端自动组合为完整物理路径传入。
2. **服务端兜底寻址**：
   - `registerLocalImportRoutes` 在处理预检（`/api/local-import/preflight`）、确认（`/api/local-import/confirm`）与新建账号（`/api/local-import/as-new-account`）时，若入参为纯文件名且在当前路径不存在，自动在 `LocalBackupService.resolvedDir` 中解析定位。
3. **文件选择器接口与默认存储路径联动**：
   - 服务端暴露 `POST /api/local-import/pick-file`，接收 `initialDir` 参数（缺省默认使用 `LocalBackupService.resolvedDir`，即程序保存备份的路径），唤起系统原生文件选择对话框（Windows Forms / macOS osascript / Linux zenity）。
   - 服务端暴露 `POST /api/local-import/upload` 支持网页端直接流式上传文件。
   - 前端导入弹窗（`LocalImportModal`）提供「选择文件...」按钮，默认唤起系统选择器并定位到程序备份目录，同时提供网页文件选择器兜底。

## 后果

### 正面影响

- 离线环境与多设备数据迁移体验完整闭环。
- 导入为新账号的轻量安全路径与覆盖当前账号的高危事务路径职责清晰，互不干扰。
- 彻底消除了因传入纯文件名导致预检 404 的问题，提升了鲁棒性与容错能力。
- 用户无需手动记忆或输入长路径，直接通过原生文件选择器即可快速定位并导入快照文件。

### 需注意的约束

- 覆盖导入操作依然是高危操作，必须先通过预检生成 `preflight.json` 记录，才允许进入确认阶段。

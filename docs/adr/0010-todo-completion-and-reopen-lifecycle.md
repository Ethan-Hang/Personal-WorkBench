# 0010. 待办事项完成、重新打开与已完成归集生命周期

日期：2026-08-18  
状态：已接受

## 背景

在个人工作台中，用户对完成事项有两大核心诉求：

1. **即时成就感与数据闭环**：完成的任务不能凭空蒸发，需要归集并参与「今日执行度」真实百分比计算；
2. **反悔与重开机制**：误勾选或重新推进的任务必须支持随时「取消完成（重新打开）」，恢复到进行中列表中。

此前 `listToday` 只查询未完成状态（`OPEN_STATUSES = ['inbox', 'todo', 'doing']`），导致已完成任务无法在界面上找到，且无重新打开的端点。

## 决策

1. **`TodayResponse` 契约扩展**：
   - 增加 `completed: TaskView[]` 字段，服务端按排程范围与本地日期查询今日已完成（`status = 'done'`）的事项；
   - `tasks` 仅包含进行中事项，`completed` 包含今日已完成事项，二者职责严格解耦。

2. **提供对称的完成与重开 HTTP 端点**：
   - `POST /api/todo/tasks/:id/complete`：将状态置为 `done` 并写入 `completedAt = now`；
   - `POST /api/todo/tasks/:id/uncomplete`：将状态恢复为 `todo` 并重置 `completedAt = null`。

3. **前端「已完成事项」专属折叠分组**：
   - 「今日待办事项」卡片下方设置独立折叠面板，默认收起以保持首页清爽专注；
   - 支持一键展开回顾成果，点击已完成项左侧绿色复选框 `[✓]` 即可无缝触发重新打开。

4. **执行度真实闭环**：
   - 今日执行度百分比公式严格定义为：`Math.round(今日已完成数 / (进行中数 + 已完成数) * 100)%`；
   - 当所有待办全部完成时，自适应呈现成就卡片。

## 后果

- **契约向后兼容**：`completed` 字段在 Zod Schema 中提供 `.default([])`，不破坏已有消费者；
- **全链路闭环**：用户无论是添加、完成、取消完成还是移入回收站，数据均在 SQLite 中完整流转，执行度仪表盘实时精准响应。
